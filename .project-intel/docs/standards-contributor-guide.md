# AutoGuard AI — Engineering Standards & Architecture Decision Records (ADRs)

## 1. Engineering Standards & Conventions
- **Strict Typing:** All components and services must maintain zero `any` leaks where feasible. Domain objects must extend interfaces in [`src/types.ts`](file:///home/def/autoinspect/src/types.ts).
- **Offline-First Resilience:** No feature should fatally crash if the internet connection is lost or if Cloud API keys are missing. Fallbacks: Ollama local runtime → LocalStorage cache → static mock / warning.
- **Defensive Parsing:** All JSON payloads generated by LLMs must pass through resilient sanitizers (e.g. `safeParseJSON` stripping markdown fences and trailing commas) with schema fallback safety nets.
- **Hardware & Resource Hygiene:** Audio contexts and video streams (`MediaStream`) must be explicitly terminated on unmount or tab switch to prevent memory leaks and background hardware locks.

## 2. Architecture Decision Records (ADRs)

### ADR-001: Hybrid Local/Cloud AI Dual Pipeline
- **Status:** Accepted
- **Context:** Dealership inspectors and field mechanics often work in underground garages, rural lots, or regions with zero/unreliable internet connectivity, while privacy-conscious users prefer vehicle photos not be sent to external clouds.
- **Decision:** Implement a unified `aiService` routing facade that checks for local Ollama server availability (`/api/ollama`) and local models (`moondream`, `llama3.2`). Fall back to Google Gemini Cloud API (`gemini-2.5-pro-preview`) when local models are unavailable or explicitly toggled.
- **Consequences:** Slightly higher client-side complexity, but provides 100% offline capability, zero cloud subscription dependency, and sub-100ms local network hops.

### ADR-002: Browser-Native Web Audio FFT Processing
- **Status:** Accepted
- **Context:** Acoustic diagnosis requires high-resolution frequency analysis (20Hz to 20kHz) without heavy server round-trips for initial audio classification.
- **Decision:** Utilize the browser's native `AudioContext` and `AnalyserNode` with `fftSize = 512` and smooth canvas rendering at 60 FPS.
- **Consequences:** Eliminates external audio streaming overhead; provides instantaneous visual feedback to the inspector; captures raw WebM blobs for AI ingestion.

### ADR-003: WMO Weather-to-Road Friction Modeling
- **Status:** Accepted
- **Context:** The tactical GPS co-pilot requires actionable road surface friction data rather than generic weather forecasts.
- **Decision:** Build a rule-based physics heuristic inside `weatherService.ts` mapping WMO standard weather codes (0–99), precipitation rate (mm/h), wind gusts (km/h), and sub-zero temperatures into a normalized road grip index (15%–99%) and enforce dynamic speed caps.
- **Consequences:** Highly responsive, zero-cost API footprint via Open-Meteo, directly actionable safety output for in-motion drivers.
